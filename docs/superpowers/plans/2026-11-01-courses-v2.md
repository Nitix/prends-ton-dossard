# Prends ton dossard v2 : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objectif :** la v2 de la feuille de route :
- prix d'une épreuve, date limite d'inscription d'un événement, rappel dans le site ;
- mode supporteur ;
- commentaires ;
- covoiturage et logement ;
- nouveau nom, « Prends ton dossard ».

**Architecture :** inchangée. Un programme Go utilise PocketBase comme bibliothèque et sert une SPA React. Le serveur porte les règles (règles d'accès PocketBase et hooks de modèle), le front masque seulement ce qui est interdit. Deux paquets Go s'ajoutent (`server/comments`, `server/offers`), quatre migrations (`9a` à `9d`) et trois dossiers de fonctionnalités côté front (`features/comments`, `features/offers`, et `features/home` qui grandit).

**Tech Stack :** Go, PocketBase v0.41.1 (`ganigeorgiev.com/pocketbase/pocketbase`), React 19 + React Compiler natif, Vite 8, TanStack Router et Query, Tailwind 4, PocketBase JS SDK 0.28, Temporal + Intl, Vitest (node et browser mode Chromium), oxlint, oxfmt.

**Spec :** `docs/superpowers/specs/2026-11-01-courses-v2-design.md` (l'addendum v2), sur la base de la spec v1 et de l'addendum v1.1. L'addendum le plus récent l'emporte.

- **Interdits** : date-fns, moment, dayjs, Biome, ESLint, Prettier, bibliothèques de formulaires, d'i18n, de Markdown ou de rendu HTML.

  - seulement à l'intérieur des fonctions et des composants, jamais au niveau d'un module ;
  - dates civiles en texte `YYYY-MM-DD` ; « aujourd'hui » = `useToday()` ; l'horloge d'un test passe par `TodayProvider` (`value`, `now`).
- **Codes d'erreur** :
  - les routes et les validations renvoient des codes, jamais de texte ;
  - les codes du serveur sont dans `server/apperr/codes.go` (une constante par ligne, `CodeX = "x"`, rien d'autre avec un `=` et des guillemets dans ce fichier) ;

- **Langues** : tous les textes viennent de `web/src/i18n/fr.ts` et `en.ts` (`en.ts` est `satisfies Messages`), ajoutés dans la même tâche que le code qui les utilise. Le formatage passe par `Intl` (`useI18n().f`).

## Review Focus

1. **Un supporteur compté comme partant** : il ferait apparaître un événement dans « Bientôt dans le groupe », gonflerait les pastilles d'une épreuve, ou bloquerait « Pas encore décidé ». Tests : `GroupSoon — un événement dont les seuls participants sont supporteurs n'est pas proposé` et `joinOptions — un supporteur n'a plus ni épreuve ni « Pas encore décidé », et pas de « Je viens encourager »` (Tasks 6 et 7). À l'inverse, le filtre `personne` doit le garder : `ListPage — ?personne=<id> garde un événement où ce coureur est supporteur` (Task 7).
2. **Le jour de la date limite** : il est encore possible de s'inscrire. « Pas passée » veut dire `deadline ≥ today`. Tests : `registrationState — le jour même, ouvert avec 0 jour restant` (Task 3) et `Inscriptions à faire — le jour de la date limite, « aujourd'hui »` (Task 4).
3. **Prix en flottants** : `19.99 × 100` vaut `1998.9999999999998`. Un contrôle « deux décimales » naïf refuserait 19,99 €. Test : la ligne `19.99` de `TestRegistrationAndPrice` (Task 2). À l'affichage, 42,5 s'écrit « 42,50 € » et 65 « 65 € » : test `price — deux décimales sauf pour un prix rond` (Task 3).
4. **Un commentaire contient du HTML ou des retours à la ligne** : il s'affiche tel quel, jamais interprété, et les lignes restent. Test : `CommentsSection — le texte s'affiche tel quel, balises comprises, avec ses retours à la ligne` (Task 9).
5. **Une place libérée ou retirée pendant qu'on regarde** : supprimer une offre emporte ses places, un coureur supprimé libère la sienne, et réduire les places sous le nombre de passagers est refusé. Tests : lignes de cascade et `offer_seats_below_members` de `TestOffers` (Task 10), et `OffersSection — Supprimer nomme les personnes qui perdent leur place` (Task 11).

## Conventions PocketBase utilisées dans les tests

Inchangées. Quand une règle refuse, PocketBase répond : **list** `200` avec une liste vide ; **view, update, delete** `404` ; **create** `400` ; **règle `null`** `403`. Une erreur de validation répond `400` avec `data.<champ>.code` (helper local `fieldError(field, code)` des tests Go). Une contrainte unique violée devient `validation_not_unique`.
