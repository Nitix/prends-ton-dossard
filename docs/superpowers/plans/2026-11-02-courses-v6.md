# « Prends ton dossard » v6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Let each person pick their theme among the eleven design variants, in three depths built from one code base (palette, mix, complete), shown on three demo instances — never in production until the user says so.

**Architecture:** « Crête » becomes the default *skin*. A skin is a folder `web/src/skins/<id>/` found by `import.meta.glob` (no shared registry to edit): its tokens and fonts, its motif components for named slots, and — by depth — CSS for semantic classes and a few markup variants. `VITE_SKIN_DEPTH` (`palette` | `mix` | `full`) decides at build time which CSS and variants are bundled. The chosen skin is stored on the device and applied before first paint, like the dark mode.

**Tech Stack:** React 19, Vite 8, Tailwind 4, the v5 app. New dependencies allowed on this branch only: the `@fontsource-variable/*` (or `@fontsource/*` when no variable build exists) packages of the variants' fonts, exact versions.

**Spec:** `docs/superpowers/specs/2026-11-02-courses-v6-design.md`. Sources of each variant: branch `design/v4-<id>` and `.superpowers/sdd/v4-designs/<id>-report.md` + screenshots.

## Global Constraints

- Every v5 constraint holds (`.superpowers/sdd/2026-11-02-courses-v5/constraints.md`).
- Branch `v6/themes` in the worktree `.superpowers/worktrees/v6`; never merge into `feat/v1`, never deploy to `prends-ton-dossard.ketra.fr`.
- With no skin chosen, the app looks exactly like v5 (Crête). Features stay common: a skin only dresses them.
- Every skin × mode passes the token contrast tests (text 4.5:1, gradient/primary buttons at rest and hover 4.5:1, dashed states 3:1, field borders 3:1, slope fills 3:1 and distinct) and forced colours.
- Fonts are served by the site (latin + latin-ext), loaded only when their skin is used.

## Review Focus

1. **Default unchanged**: Crête at every depth renders like v5 (tests unchanged, screenshots compared).
2. **A skin breaks a feature**: the D+ chart, map link, forms, dialogs work under every skin (a smoke battery per skin).
3. **Contrast per skin and mode** (parameterised tests).
4. **No flash**: a stored skin applies before first paint.
5. **Bundle**: palette depth adds only small CSS; fonts load on demand.

### Task 1: Skin architecture, Crête as default, the picker

- `web/src/skins/types.ts` (`Skin`: `id`, `label: {fr,en}`, `modes: ("light"|"dark")[]`, `slots?: Partial<Slots>`), `web/src/skins/index.ts` (glob registry, `useSkin`, `applySkin`, `readSkin`, `SKIN_DEPTH`), `web/src/skins/crete/` (current tokens/motifs moved behind the skin, no visual change).
- Slots: `HeaderArt`, `BrandMark`, `HeroArt`, `Divider`, `SectionMarker`, `EmptyArt` — components ask `useSlot(name)` with Crête's as fallback.
- Semantic classes added to the signature pieces (`.app-header`, `.tabbar`, `.event-card`, `.event-hero`, `.page-title`, `.section-title`, `.stat-tile`, `.chip`, `.btn-primary`…), styled by Crête's CSS, so deeper skins can restyle them.
- Depth: CSS files `skins/<id>/{palette,mix,full}.css` bundled according to `VITE_SKIN_DEPTH` (Vite `define` + glob filtering).
- Réglages → Apparence: « Thème » (cards with name, two colours, font sample) above « Clair / Sombre / Auto » (shown when the skin has both modes). Stored in `localStorage["ptd-skin"]`, applied by the inline script.
- Tests: registry, no-flash script, picker, parameterised contrast over every skin × mode, default unchanged.

### Task 2: Fonts of all variants

- Add the font packages of every variant (from their `index.html`), self-hosted like Task 2 of v4, one `@font-face` file per skin, loaded with the skin.

### Task 3: Palette depth — the ten other skins

- One `skins/<id>/` per variant: tokens (light, and dark if the variant had one — Nuit is dark only), fonts, motif slots ported from `design/v4-<id>` (header art, brand mark, hero art, divider, section marker, empty art). Can be split across agents by skin (disjoint folders).

### Task 4: Mix depth — signature pieces

- Per skin, `mix.css` (and slot variants if markup must differ) for the header, tab bar, event card, event hero, section titles, from the variant's branch.

### Task 5: Complete depth

- Per skin, `full.css` and markup variants for every other piece the variant restyled (dialogs, chips, stats tiles, forms, agenda, admin…), keeping v5's features (D+ chart, map link, measures, period line).

### Task 6: Three demo instances

- `ptd-v6-palette`, `ptd-v6-mix`, `ptd-v6-complet` `.ketra.fr`, each built with its `VITE_SKIN_DEPTH`, seeded, with a GPX; Caddy routes; no `DEMO_LOGIN_EMAIL` unless the user asks (password-only demo accounts like the other design demos).
