# Courses entre amis v1 : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objectif :** un site privé, pensé pour le mobile, où un groupe d'amis planifie ses courses et trails. Il gère les comptes sur invitation, les participations avec confirmation, les vues liste et agenda, une partie admin, et la connexion par mot de passe ou passkey.

**Architecture :** un seul programme Go qui utilise PocketBase comme bibliothèque (SQLite, comptes, règles d'accès), complété par des hooks et des routes sur mesure (invitations, passkeys, fusions). Il embarque et sert une SPA React. Le front ne fait qu'afficher : toutes les règles sont appliquées côté serveur. Le déploiement se fait par une image Docker derrière Caddy.

**Stack :**
- **Serveur** : Go, PocketBase v0.41.1 (module `ganigeorgiev.com/pocketbase/pocketbase`, plus sur GitHub ; API « core » apparue en 0.23), `go-webauthn/webauthn`.
- **Front** : TypeScript, React 19 avec le React Compiler, Vite (Rolldown), Tailwind 4, TanStack Router et Query, SDK JS de PocketBase, Temporal (+ `temporal-polyfill`), Intl.
- **Outils** : oxlint et oxfmt, Vitest (node et browser mode), Playwright, pnpm, Node ≥ 26.

**Spec :** `docs/superpowers/specs/2026-10-31-courses-design.md`. Lis-la avant chaque tâche : le plan renvoie à ses sections (§).

## Global Constraints

- Node ≥ 26 (`engines` dans `package.json` et `.nvmrc` = `26`), pnpm. Go en dernière version stable. Toutes les dépendances sont prises en dernière version stable au moment de la Task 1 ou de la Task 11, puis verrouillées.
- Interdits : date-fns, moment, dayjs, Biome, ESLint, Prettier, bibliothèques de formulaires ou d'i18n.
- Dates de course : texte `YYYY-MM-DD` en base, `Temporal.PlainDate` côté front. « Aujourd'hui » = `Temporal.Now.plainDateISO("Europe/Paris")`.
- Aucun envoi d'email. Les invitations et réinitialisations se font par un lien à partager à la main.
- Jeton d'invitation : 32 octets aléatoires en base64url. Seul son SHA-256 (hexadécimal) est stocké. Valable 7 jours, à usage unique.
- Mot de passe : 10 caractères minimum.
- Défis WebAuthn : en mémoire, durée de vie de 5 minutes. `residentKey: required`, `userVerification: preferred`.
- `APP_URL` donne l'origine WebAuthn et l'identifiant du site (son nom d'hôte). Par défaut : `http://localhost:5173`.
- Ports : PocketBase `:8090`, Vite `:5173`.
- Les routes sur mesure et les validations renvoient des **codes** d'erreur, jamais de texte. La liste unique est dans `server/apperr/codes.go`, et le front les traduit.
- Langues : `fr` et `en` détectées depuis `navigator.languages`, `fr` par défaut. Tous les textes viennent des dictionnaires `web/src/i18n/{fr,en}.ts` (aucun texte en dur dans les composants). Tout le formatage passe par `Intl`, dans la locale de formatage.
- Accessibilité : zones tactiles d'au moins 44 px ; l'état « non confirmé » n'est jamais signalé par la couleur seule ; fenêtres en `<dialog>` natif.
- Le front masque les actions interdites mais n'est jamais garant d'une règle.
- Chaque commit est signé (GPG, ne jamais le contourner) et son message se termine par :
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`

## Review Focus

1. **Compte désactivé avec une session ouverte** : la session doit cesser de marcher tout de suite. Test dans la Task 5 (`TestUsers_DisableInvalidatesSessions`).
2. **Le dernier admin se retire le rôle ou se désactive** : refusé avec `last_admin`, sinon plus personne ne peut administrer le site. Test dans la Task 5.
3. **Des dates d'événement modifiées font sortir une épreuve datée de la plage** : refusé avec `format_date_out_of_range`. Test dans la Task 4.
4. **Une invitation refusée (email déjà pris), puis réessayée ; ou un double clic sur « Valider »** : la première erreur ne doit pas consommer le lien, et un second envoi réussi est impossible. Tests dans la Task 7.
5. **Juste après minuit à Paris** (22 h 30 UTC la veille d'une course en été) : la course est « aujourd'hui » et toujours à venir. Test dans la Task 12.

## Conventions PocketBase utilisées dans les tests

Quand une règle refuse, PocketBase répond :
- **list** : `200` avec une liste vide ;
- **view, update ou delete** : `404` ;
- **create** : `400` ;
- **règle `null`** (réservé au super-admin) : `403`.

Si la version installée répond autrement, on asserte le code observé, mais la sémantique doit rester la même (autorisé ou refusé).

### Task 4 : Codes d'erreur, hooks des événements et des épreuves

**Files :**
- Create : `server/apperr/apperr.go`, `server/apperr/codes.go`, `server/events/hooks.go`
- Modify : `server/setup/setup.go` (appelle `events.Register`)
- Test : `server/events/hooks_test.go`

**Interfaces :**
- Produces :
  - `apperr.New(status int, code string) error` → `router.ApiError` avec `data = {"code": code}`
  - `apperr.Field(field, code string) error` → `validation.Errors{field: validation.NewError(code, code)}`
  - une constante `apperr.Code…` par code de la liste d'en-tête, par exemple `apperr.CodeLastAdmin = "last_admin"`
  - `events.Register(app core.App)`
  - `events.RunnerOf(app core.App, userID string) (*core.Record, error)` : le coureur dont `user = userID`, ou `nil` sans erreur

**Comportement :**
- **Hook de requête de création sur `events`** : `created_by` reçoit `RunnerOf(auth)` ; s'il n'y en a pas (super-admin), le champ reste vide.
- **Hook de requête de mise à jour sur `events`** : `created_by` reprend sa valeur d'origine.
- **Hooks de validation du modèle**, sur `events` comme sur `formats` :
  - une date qui ne correspond pas à `^\d{4}-\d{2}-\d{2}$`, ou qui n'existe pas (`time.Parse("2006-01-02")`) → `Field(<champ>, date_invalid)` ;
  - `end_date < start_date` → `Field("end_date", end_before_start)` ;
  - événement modifié alors qu'une de ses épreuves a une `date` hors de la nouvelle plage → `Field("start_date", format_date_out_of_range)` ;
  - épreuve dont la `date` sort de la plage de son événement → `Field("date", format_date_out_of_range)`. Sans `end_date`, la plage est `[start_date, +∞[`.
  - épreuve sans `distance_km`, sans `duration_min` et sans `time_limit_min` → `Field("distance_km", format_measure_required)`.

```ts
export function newId(): string;   // 15 caractères [a-z0-9] tirés avec crypto.getRandomValues (format des id PocketBase)
export function toMinutes(hours: number | undefined, minutes: number | undefined): number | undefined; // undefined si les deux sont vides ou à 0
export function fromMinutes(total: number | undefined): { hours?: number; minutes?: number };
export function DurationInput(props: { name: string; label: string; value?: number; onChange(v: number | undefined): void }): JSX.Element; // deux <input type="number"> h et min
export function significantWords(name: string): string[];  // mots \p{L}+ d'au moins 4 lettres, en minuscules, sans doublon
export function duplicateFilter(name: string, date: Temporal.PlainDate, excludeId?: string): string | null; // null si aucun mot ; ±30 jours
export type BatchOp = { action: "create" | "update" | "delete"; collection: "events" | "formats" | "participations"; id: string; body?: Record<string, unknown> };
export type EventDraft = { id?: string; name: string; location: string; start_date: string; end_date?: string; registration_url?: string; notes?: string;
  formats: { id?: string; name?: string; race_type: string; distance_km?: number; duration_min?: number; time_limit_min?: number; elevation_gain_m?: number; date?: string }[];
  join?: { formatIndex: number; status: Status } };

```

**Comportement :**
- **Atomicité** : création et modification passent par **une seule requête batch** PocketBase. Les nouveaux id sont générés côté client (`newId`), ce qui permet aux épreuves et à la participation de référencer l'événement dans le même lot.
- **Épreuves retirées** dans le formulaire → opérations `delete` dans le lot.
- **Au moins une épreuve** : le bouton « Retirer » est désactivé quand il n'en reste qu'une.
- **Champs d'une épreuve** : type, distance, durée et temps max (`DurationInput`), D+, date. Si aucune des trois mesures n'est remplie, le formulaire affiche `t.errors.format_measure_required` avant même l'envoi. Le serveur reste le garant de la règle.
- **Doublons** : la recherche se déclenche 400 ms après la dernière frappe, une fois le nom et la date remplis, avec `duplicateFilter` et `excludeId` en modification. `DuplicateHint` affiche `t.form.duplicateQuestion` et des liens vers les fiches.
- **« Je participe »** : coché par défaut à la création, avec le choix de l'épreuve. Absent en modification.
- **Erreurs** : `fieldErrors` est affiché sous chaque champ, et les valeurs saisies restent (l'état de `useActionState` réinjecte le brouillon).

  - `fromMinutes(2790)` → `{hours: 46, minutes: 30}` ; `fromMinutes(undefined)` → `{}`.
