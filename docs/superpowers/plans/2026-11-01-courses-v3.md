# Prends ton dossard v3 : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objectif :** la v3 de la feuille de route :
- résultats (temps, classement) et statistiques annuelles par personne ;
- trace GPX par épreuve, avec son tracé et son profil de dénivelé, ou un lien de parcours ;
- export vers un agenda (iCal) ;
- installation sur l'écran d'accueil (PWA).

**Architecture :** inchangée (programme Go avec PocketBase en bibliothèque, SPA React). Trois migrations (`9e` à `9g`), un paquet Go (`server/calendar`, routes et flux iCalendar), un outil Go (`tools/icons`). Côté front : `features/results`, `features/stats`, `features/runners`, `features/route` (trace), `features/calendar`, `features/pwa`, un service worker dans `web/public/sw.js`.

**Tech Stack :** Go, PocketBase v0.41.1 (`ganigeorgiev.com/pocketbase/pocketbase`), React 19 + React Compiler natif, Vite 8, TanStack Router et Query, Tailwind 4, PocketBase JS SDK 0.28, Temporal + Intl, Vitest (node et browser mode Chromium), oxlint, oxfmt.

**Spec :** `docs/superpowers/specs/2026-11-01-courses-v3-design.md` (addendum v3), sur la base de la spec v1 et des addendums v1.1 et v2.

## Global Constraints

Les contraintes de la v2 restent valables mot pour mot (`docs/superpowers/plans/2026-11-01-courses-v2.md`, « Global Constraints »), en particulier : commandes préfixées par `env.sh` ; **aucune dépendance nouvelle** (Go comme front) ; Temporal jamais au niveau d'un module ; codes d'erreur serveur ajoutés au front dans le même commit ; tous les textes en fr et en en ; zones tactiles de 44 px, jamais la couleur seule, `<dialog>` natif, focus jamais perdu sur `<body>` ; boutons d'envoi en `aria-disabled` + garde synchrone (pas `disabled`) ; clauses de propriétaire gardées par `@request.auth.id != ""` ; règles des nouvelles tables dans leur migration ; migrations `9e_…`, `9f_…`, `9g_…` avec retour arrière testé et listes de `migrations_test.go` à jour ; hooks de modèle pour les invariants ; ports 8090/5173 seulement ; jamais de WebAuthn réel ; jamais le site déployé ; commits signés avec la ligne `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, fichiers ajoutés un par un, jamais `docs/superpowers/specs/2026-10-31-courses-design.md`.

En plus pour la v3 :
- **Graphiques** : le tracé et le profil sont du SVG écrit à la main (pas de bibliothèque de graphiques). Avant d'écrire leur code, charger la compétence `dataviz` et suivre ses règles (couleurs du thème, contraste, lisibilité en clair et en sombre, axes).
- **Fichiers** : la trace se lit dans le navigateur (`DOMParser`), jamais côté serveur.
- **Service worker** : n'est enregistré qu'en production (`import.meta.env.PROD`) ; aucun test ne doit en enregistrer un dans le navigateur de Vitest.

## Review Focus

1. **Un résultat qui survit à un changement de statut** : un temps sur un « Abandon » fausserait les statistiques. Test : les lignes « changing the status clears the result » de `TestParticipations_Results` (Task 1) et `stats — un abandon ne compte que dans les abandons` (Task 4).
2. **Une trace GPX sans altitude, en `rtept`, ou vide** : la fiche ne doit pas planter, seulement montrer ce qu'elle peut. Tests : `parseGpx — sans altitude`, `parseGpx — rtept`, `parseGpx — fichier invalide` (Task 6) et `EventPage — une trace illisible affiche un message, pas d'erreur` (Task 7).
3. **Le D+ d'un GPS bruité** : additionner chaque petite variation double le D+. Test : `gpxStats — le bruit sous 3 m ne compte pas` (Task 6).
4. **Le flux d'agenda** : un `UID` qui change à chaque lecture crée des doublons dans l'agenda ; une virgule ou un retour à la ligne non échappé casse le fichier. Tests : `TestCalendarFeed` (Task 8).
5. **Le service worker garde une vieille version ou une réponse de l'API** : après un déploiement, la page ne doit pas rester bloquée sur l'ancienne version, et une donnée ne doit jamais venir du cache. Tests : `sw — l'API passe toujours par le réseau`, `sw — une page vient du réseau d'abord` (Task 10) et `TestSPA_ServiceWorkerHeaders` (Task 10).

## Conventions

Inchangées (v2) : PocketBase répond `200` liste vide, `404`, `400`, `403` selon la règle ; une erreur de validation répond `400` avec `data.<champ>.code` ; tests Go par `testutil.RunRows` ; tests front avec leur propre `render` et un `vi.mock` de `lib/pb`.
