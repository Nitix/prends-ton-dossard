# « Prends ton dossard » v4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the design « Crête » as the real v4: a green test suite, fonts served by the site, AA contrast for the slope chart and the dashed states, and focus that follows navigation.

**Architecture:** The design is already on `feat/v1` (fast-forward of `design/v4-crete`, f407ea5): tokens in `web/src/styles.css`, motifs in `components/Alpenglow.tsx`, `Brand.tsx`, `RidgeDivider.tsx`, `motifPaths.ts`, the slope-coloured profile in `features/route/ElevationProfile.tsx` + `slope.ts`. This plan hardens it; it does not redesign.

**Tech Stack:** React 19, Vite 8, Tailwind 4, TanStack Router/Query, Vitest (node + Chromium browser), Go/PocketBase (unchanged).

**Spec:** the user's choice (2026-11-01): « Le nouveau thème est crete ! » — the design is documented in `docs/superpowers/designs/2026-11-01-v4-crete.md` (built on `2026-11-01-v4-aurore.md`). Other variants stay on their branches and demo instances: never delete them.

## Global Constraints

- Every constraint of `.superpowers/sdd/2026-11-01-courses-v3.1/constraints.md` holds (tools, i18n, 44 px, `aria-disabled` + ref guard, focus never on `<body>`, signed commits staged one by one, never stage `docs/superpowers/specs/2026-10-31-courses-design.md`).
- New dependencies allowed in this plan: `@fontsource-variable/inter` and `@fontsource-variable/plus-jakarta-sans`, exact versions (5.3.0 at writing). Nothing else.
- Tests may change when they pin markup or classes the design changed; a test that pins behaviour or accessibility (44 px, focus, roles, names, announcements, no horizontal overflow) keeps its assertion, and the code is fixed instead.
- No Google Fonts or other third-party requests from the app shell.

## Review Focus

1. **A test "fixed" by weakening it**: a 44 px, focus, role or name assertion relaxed to match the new look. Check: diff of every changed test (Task 1).
2. **Fonts offline**: the installed app opened offline must keep its fonts (served from `/assets/`, cache-first). Test: `fonts — no request leaves the site` + build output check (Task 2).
3. **Slope colours**: each zone fill ≥ 3:1 against the white card and distinct from its neighbours for colour-blind vision. Test: `slope — every zone colour has 3:1 against white` (Task 3).
4. **Focus on navigation**: moving to another page focuses its `h1`, but the first load and an in-page change (filters, dialogs) do not steal focus. Tests in Task 4.
5. **Floating tab bar vs content**: on a phone the last item of a page is not hidden under the floating tab bar or the + button. Test: an AppShell/page test that the main area's bottom padding clears both (Task 1).

The user: « pour le thème dark ne change pas la couleur de l'entête en violet avec les effets de dénivelé ». Choices made with the user: before the v4 deploy; follows the phone's setting by default, with « Auto / Clair / Sombre » in Réglages.

**Interfaces:**

- [ ] **Step 1: failing tests**: `theme — auto suit le réglage du système`; `theme — le choix est gardé sur l'appareil`; `SettingsPage — Apparence : Auto, Clair, Sombre`; contrast tests on the dark tokens (body text ≥ 4.5:1, muted text ≥ 4.5:1, dashed borders ≥ 3:1 on the dark card and sheet, each slope fill ≥ 3:1 on the dark card and distinct as in Task 3, white text on the gradient buttons unchanged).
- [ ] **Step 2: implement.** The header sky (dawn gradient, contours, ridges, sun, wordmark) is the same in both themes.
